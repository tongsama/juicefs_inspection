# v1.4.1-kaz.2

v1.4.1-kaz.1 に、writeback の staging ブロックを OS クラッシュから守る修正を加えた版です。kaz.1 の改修はすべてそのまま含みます（変更点は [v1.4.1-kaz.1 のリリースノート](https://github.com/tongsama/juicefs_inspection/releases/tag/v1.4.1-kaz.1) を参照）。

## 既定で変わる動作

- `--writeback-fsync`（既定 `true`）：`--writeback` のとき、書き込みの完了を返す前に、staging ブロックを `fdatasync` し、その親ディレクトリ（と、この process でまだ確定させていない上位ディレクトリ）を `fsync` します。
  - 従来は sync していませんでした。そのため、juicefs を動かしている OS がクラッシュしたり電源が落ちたりすると、直前（Linux の既定で約 30 秒以内）に書いた staging が 0 バイトのファイルとして残ることがありました。その場合、そのブロックのデータは失われます。実際に WSL のクラッシュで発生しています。
  - sync に失敗したときは、そのブロックをローカルに置かず、直接 object storage へアップロードします。エラーは隠しません。
  - 読み取りキャッシュの書き込みは対象外です（失っても object storage から取り直せるため）。

## 注意

- **書き込みのレイテンシが増えます。** staging ブロック 1 つにつき、`fdatasync` 1 回とディレクトリの `fsync` 1 回以上が加わります。小さいランダム書き込みが多い用途（VM イメージなど）では影響が出る可能性があります。性能を優先して従来の動作に戻すには `--writeback-fsync=false` を指定してください（OS クラッシュで staging を失う可能性を受け入れることになります）。
- 実際の VM 負荷でのレイテンシと PUT への影響は、まだ計測していません。
- このほかの注意（Windows 版の mount は未検証、armv7・macOS 向けはなし、稼働中の mount の置き換えなど）は kaz.1 と同じです。
