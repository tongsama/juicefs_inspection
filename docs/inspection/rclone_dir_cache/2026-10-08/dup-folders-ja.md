# Drive 上の同名フォルダの重複の確認（2026-10-08）

- 目的: 複数ホストが同時に新しいフォルダを作ることによる、同じ親の下の同名フォルダの重複が、実際に起きているかを確かめる（仕様 §7）。
- 方法（読み取りのみ、ユーザー承認済み）: 2026-10-08 12:12:17〜12:18:30 JST に、手元の `/usr/bin/rclone`（v1.75.1）で
  `rclone backend query gdrive_kwatan: "mimeType='application/vnd.google-apps.folder' and trashed=false" --tpslimit 2 --low-level-retries 3`
  を実行し、ドライブ全体のフォルダ一覧（JSON、36,997,249 バイト、SHA-256 先頭 `21d9906e5232c83a`）を取得した。生の JSON はフォルダ名と ID を含むので、このリポジトリには置かない（scratchpad のみ）。
- 集計: [dup_folders_analyze.py](dup_folders_analyze.py) で `rclone-s3` の配下をたどり、同じ親で同じ名前のフォルダを数えた。

## 結果（観測）

| 項目 | 値 |
|---|---|
| ドライブ全体のフォルダ数（ごみ箱を除く） | 100,503 |
| `rclone-s3` という名前のフォルダ | 1（My Drive の直下、作成 2026-09-19） |
| `rclone-s3` 配下のフォルダ数（自身を含む） | 1,442 |
| 深さ別（rclone-s3 からの深さ 1〜5） | 1 / 1 / 3 / 7 / 1,429 |
| **同じ親で同じ名前のフォルダ** | **0** |

## 解釈と限界

- 取得した時点では重複は無い。
- ごみ箱に入ったフォルダ・完全に削除されたフォルダは対象外。過去に重複が起き、`rmdirRecursive` で消えた可能性までは否定できない。
- 発生条件（境界のフォルダを2台が共有し、最初の PUT がほぼ同時）は source 上は成り立つ。複数台の運用期間が短い、またはタイミングが重なっていない可能性がある。発生しないことの保証ではない。
